# Packet family 04 — Complete product surfaces

## Outcome

Today, Jobs, Applications, Coverage, onboarding/auth, Settings, landing, and system
routes are complete on laptop and phone with no placeholder feature.

## Atomic packets

### PKT-04A Today

Implement design-defined new roles, Autopilot review work, and product-derived
application/referral follow-ups. Counts/badge/query/freshness share one contract.
Gmail-derived suggestions are absent. Prove decision replay, undo, focus, two tabs,
provider degradation, empty sections, and phone use.

### PKT-04B Jobs integration

Replay the Jobs redesign onto the integrated schema. Enforce six columns and four
controls plus Display, exact copy, saved-view/filter/URL round trip, 420px pane, Escape
focus, `Not listed`, logo ladder, warm indicator, export scope equality, formula safety,
large type, and phone behavior.

### PKT-04C Applications

Implement exact status bands/pane/row affordances, manual add/import/status/notes,
activity/evidence, conflict/undo, attachment association, export, empty/degraded states,
and no Gmail-monitoring claim.

### PKT-04D Coverage

Implement three-tab design, company review/monitoring, coverage sentence, source/freshness,
per-user activity, blind spots/recovery, company pane, connections/referral entry, and
no Sheet language.

### PKT-04E Onboarding/profile

Support any US role family/seniority and remote/hybrid/on-site. Fields include role/work
description, geography, pay, work model, and relevant deal-breakers. Preview and engine
use the same deterministic corpus. Criteria changes affect new roles by default;
re-gating existing roles requires explicit confirmation.

### PKT-04F Settings/account

Profile, display, notifications, connected accounts without Gmail mailbox, answers,
plan, data archive, deletion, support, privacy, and terms. All writes use frozen
versioned commands.

### PKT-04G Landing/auth

Public landing, signup, sign-in, recovery, pending holding, suspended, activation, and
legal/support routes. Screenshots are real product frames. Product/plan claims match
deployed capability.

## Required verification

Each child packet needs strict design manifest, fixture/live parity, reload proof for
persistence, WCAG 2.2 AA, touch/keyboard, phone/desktop, authorization negatives,
dependency failure, and a controlled violating fixture.
